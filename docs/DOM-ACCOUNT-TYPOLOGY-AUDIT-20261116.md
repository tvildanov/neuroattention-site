## Как работает вводный тест

Источник: `test.html`, `QUESTIONS`, `scoreAnswer`, `computeProfile`, `finishTest`, `saveResultToAPI`.

11 основных вопросов: фильтр Q0 + Q1–Q10. Фильтр может открывать дополнительный сбор сведений для реабилитации. Утверждение «10 вопросов» относится к Q1–Q10.

Ответы A/B/C/D преобразуются в 4/3/2/1. В общий `total` входят девять вопросов: Q1–Q8 и Q10; диапазон 9–36. Q9 задаёт интерес к работе специалистом и исключён из общей суммы. Q0 не участвует в классификаторе.

| Внутренняя группа | Вопросы | Диапазон |
|---|---|---|
| state | Q1, Q3, Q5 | 3–12 |
| attention | Q2, Q4 | 2–8 |
| discipline | Q6, Q8 | 2–8 |
| environment | Q7, Q10 | 2–8 |
| specialist | Q9 | 1–4; это кодировка интереса, не функциональная способность |

Важная неоднозначность: Q4 спрашивает о связи с телом, но включён в группу `attention`; `environment` объединяет использование технологий и наличие опоры/поддержки. Эти группы не являются тремя слоями или 13 отдельными характеристиками.

Правила применяются строго по порядку:

1. Q9=C/D и total≥24 → FUTURE_SPECIALIST.
2. Иначе total≥30 → STABLE_EXPLORER.
3. Иначе все Q1/Q3/Q5=C/D → NERVOUS_SYSTEM_SENSITIVE.
4. Иначе оба Q2/Q4=C/D → DISTRACTED_EXPLORER (отображение: FRAGMENTED FOCUS).
5. Иначе → HIGH_LOAD_ADAPTER.

Например, все A дают STABLE_EXPLORER; замена только Q9 на D даёт FUTURE_SPECIALIST при неизменной общей сумме 36. Это подтверждает смешение функционального состояния с профессиональным интересом. Это описание существующего алгоритма, а не рекомендация сохранить его для глубокой диагностики.

## Как появляются 13 чисел

`loadTestProfile` → `/api/test-result/latest` → `showTestProfileCard` → `rpgLoadStats` → `/api/stats/me`. При 404 вызывается `/api/stats/init`.

`/api/stats/init` копирует объект из `data/profile-stats.json` в `user_stats`. Например, STABLE_EXPLORER всегда начинает с Stability=70, Interoception=60, Attention Control=70 и т. д. Разные ответы, попавшие в один тип, получают одинаковый шаблон. WMC тоже задан в шаблоне (1 или 2), отдельного оценивания нет.

| Группа | Ключи |
|---|---|
| BODY CORE | stability, energy_regulation, interoception, proprioception, vital_engagement |
| MIND CONTROL | attention_control, awareness, adaptation_flexibility, execution |
| WORLD | technoperception, socioperception, relational_awareness, space_awareness |

В БД `test_results` сохраняет историю опросов; `user_stats` хранит один текущий набор чисел на пользователя. Нет версии метода, источника каждой оценки, уверенности, привязки к исходному тесту и истории изменений оценок. `updated_at` относится ко всему набору.

## Подтверждённые разрывы

| Приоритет для пилота | Наблюдение | Последствие |
|---|---|---|
| Высокий | 13 чисел назначаются шаблоном типа | Экран выглядит точнее, чем фактическая диагностика |
| Высокий | При ошибке загрузки `rpgRenderFallbackStats` показывает такие же шаблонные числа без отдельной метки источника | Сбой API визуально может выглядеть как нормальный персональный профиль |
| Высокий | `/api/stats/init` ничего не меняет, если строка уже существует | После повторного теста имя берётся из последнего результата, числа могут остаться от первого |
| Высокий | `/api/test-result/save` принимает присланные profile/answers/scores без серверного пересчёта и проверки согласованности | Итог на сервере не гарантированно соответствует ответам |
| Высокий | Несколько путей переноса `na_test_result` в кабинете передают только profile/answers/scores | Поля rehab из гостевого результата могут потеряться при переносе |
| Высокий | Нет idempotency ключа сохранения; несколько путей отправки | Есть риск дублей при регистрации/повторной отправке; конкурентный сценарий в production не проверялся |
| Средний | `PATCH /api/stats/:stat` допускает любой ключ и число 0–100 для собственного пользователя | Нет каталога допустимых показателей и происхождения изменения; это не позволяет менять чужие записи |
| Средний | `/api/stats/init` разрешает profileKey из тела запроса перекрыть результат БД | Серверный профиль не является единственным источником выбора шаблона |
| Средний | Конфигурация дублирована в JSON, fallback кабинета и встроенных данных главной | Возможен дрейф; на базе аудита данные главной совпадают с JSON |
| Проверить при реализации | API читает `../data/profile-stats.json`, Railway root `/api` | Нужно проверить доступность файла в реальном build context; неисправность не доказана без логов/init |

Когнитивные упражнения имеют `score`, accuracy, reaction_time_avg, duration_ms, raw_data и персональную историю. Сервер также вычисляет грубый percentile по лучшим результатам пользователей, без фильтра уровня в текущем SQL; это не нормативный показатель 13-мерной модели. Скрининги хранят собственные ответы/суммы и не должны автоматически превращаться в общий профиль.

## Демонстрации главной

- `index.html#xr2-data` содержит встроенную копию пяти шаблонов и метаданных всех 13 характеристик.
- `assets/js/dom-xr-guided.js` даёт исследовать эти примеры и их показатели. Это не измерение пользователя.
- `assets/js/dom-home-refinements.js` назначает четырём портретам демонстрационные сценарии из тех же шаблонов; они не являются оценками членов команды.
- `assets/js/dom-xr-scene.js` показывает концепт XR с демонстрационными сигналами, без получения биометрических данных.
- Пробная запись ощущения/контекста на главной не становится автоматически персональным диагностическим результатом кабинета.
- Текст некоторых CTA обещает узнать собственные показатели в тесте, хотя сейчас тест выбирает шаблон. Исправление содержания главной согласовать отдельным пакетом с работой главной.

- Layer B — более глубокая исходная диагностика, Self-Guided/Guided; прежний ориентир 40–90 минут, не утверждённая длительность нового пилота.
- Layer C — уточнение по длительным наблюдениям и поведению.
- Оценки характеристик отдельно от профиля, XP и WMC. Профиль должен меняться вслед за конфигурацией измерений.
- 12 базовых профилей в целевой модели. Их канонические имена, пороги и граф преобразований в документе не восстановлены. Пять типов сайта не следует объявлять этими двенадцатью.
- WMC — самостоятельный метапараметр с четырьмя уровнями; математическое влияние не завершено.
- Не завершены Space Awareness, общая система scoring/confidence, dependency matrix и ряд протоколов. Участие в практике само по себе не доказывает рост способности.

Названия исходных чатов пока не восстановлены надёжно. Есть ориентир: обсуждение подготовки handoff 26 августа 2026, примерно 16:17–16:20 UTC. Более ранние обсуждения 16 шкал ощущений — соседняя линия материалов, не готовая замена этой модели.
