# DOM Typology — переносимая рабочая спецификация

Версия 0.3, 16 ноября 2026. Владелец замысла: Никита.

Цель: вместе достроить систему типирования до удобного инструмента участника DOM Institute и подготовить воспроизводимые инструкции для агента или нескольких агентов на разных хостах. Это начало разработки методики и будущего skill, не установленный skill, диагностический движок или запущенная мультиагентная система.

## Текущая точка продолжения

Сначала прочитать [CONTINUE.md](CONTINUE.md): новые требования Никиты, порядок совместной работы и один ожидающий вопрос FQ01. После каждого содержательного ответа обновлять эту точку и сохранять изменения в GitHub. Не требовать от основателя восстанавливать весь архив.

## С чего начать на новом хосте

1. Прочитать [полный handoff, полученный текстом из сообщения](sources/2026-08-26-handoff-chat-transcription.md), [его разбор](HANDOFF-REVIEW.md) и [контракт будущего агента](AGENT-CONTRACT.md).
2. Проверить [решения и нерешённые вопросы](DECISIONS.md).
3. Использовать [реестр источников](SOURCES.md); не считать метаданные прочитанным документом.
4. Для методики Homo Conscius прочитать [заметки](sources/2026-11-16-homo-conscius-notes.md) и [новые уточнения Никиты](sources/2026-11-16-user-requirements.md).
5. Для состояния реализации прочитать [аудит](../DOM-ACCOUNT-TYPOLOGY-AUDIT-20261116.md) и [продолжение](../DOM-ACCOUNT-TYPOLOGY-HANDOFF.md). Перед изменениями проверить свежий код: аудит фиксирует определённый SHA.
6. Для связей с другими системами прочитать [контракт интеграции](INTEGRATION.md).

Markdown и JSON читаются без ChatGPT, Library, Монады или конкретной модели. Копирование этой папки переносит текущие документы, но не полные байты внешних исходников: их покрытие явно указано в реестре. Пока новые исходники не собраны полностью, экспорт не является полным архивом метода.
